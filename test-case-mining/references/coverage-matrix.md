# Coverage Matrix

固定一份覆盖维度，每个被测对象逐格打 `已测 / 未测 / 不适用`，避免遗漏。

## 维度定义

| 维度 | 含义 | 典型用例 |
|---|---|---|
| **Happy Path** | 主流程、正常输入、正常返回 | 基本输入下的正确输出 |
| **边界** | 空、单元素、最大、最小、负数、超长、Unicode、零值 | 空集合、`len == 1`、`MAX_INT`、空字符串、含表情符 |
| **错误路径** | 显式抛错、错误码、降级 | 依赖失败、参数非法、超时、取消 |
| **状态转移** | 状态机合法 / 非法迁移、初始 / 终止 | 重复初始化、未初始化即调用、顺序依赖 |
| **幂等与重试** | 多次调用结果一致、可安全重放 | 重复提交、网络重试、消息重复消费 |
| **并发 / 顺序** | 多协程 / 多线程、消息乱序、读写竞争 | race detector、并发 map、channel 顺序 |
| **安全** | 注入、越权、路径穿越、反序列化、敏感信息泄漏 | SQL 注入、`../`、过长输入、密钥日志 |
| **I18n / 时区 / 编码** | 多语言、UTC vs 本地、多字节字符、夏令时 | 时区切换、UTF-8 边界、`zh-CN` vs `en-US` |
| **性能 / 大输入** | 大集合、长字符串、高并发；按需 | 万级元素、`O(n²)` 退化、内存峰值 |
| **兼容** | 旧格式、缺字段、多版本、向后兼容 | 历史数据、可选字段缺失、协议升级 |

## 判格规则

- **已测**：现有测试覆盖该维度，并能在断言中真正区分通过与失败。
  - 反例：测试只调用了函数但没断言对应行为，**算未测**。
  - 必须标出证据：`测试文件:line` + 断言点；找不到证据就不能标 `✓`。
- **未测**：源码存在该维度的可能性，但没有对应断言。
- **不适用**：该对象在该维度上无意义（如纯函数无并发、无 I/O 的逻辑无安全注入）。需要写一句理由。
- **未知**：范围或依赖不足以判断时用 `?`，并列入开放问题；不要猜。

## 输出形式

```markdown
| 对象 | Happy | 边界 | 错误 | 状态 | 幂等 | 并发 | 安全 | I18n | 性能 | 兼容 |
|---|---|---|---|---|---|---|---|---|---|---|
| OrderService.Create | ✓ `order_test.go:18` | ✗ | ✗ | n/a 无状态机 | ✗ | ✗ | n/a 无鉴权输入 | n/a | n/a | n/a |
```

- `✓` 已测
- `✗` 未测，需补
- `n/a` 不适用（在脚注里给一句理由）
- `?` 信息不足，需要用户或上下文补充

## 优先级映射

- **P0 必须**：Happy + 错误路径 + 已知 bug 回归 + Scout 标 Critical/High 的假设。
- **P1 应当**：边界、状态转移、幂等、安全（若适用；安全高风险可升 P0）。
- **P2 可以**：I18n / 时区、性能、兼容（按业务风险）。
